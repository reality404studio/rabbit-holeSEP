# v8 — v7「에디션」폴리싱 기록

기준본: `_sepzip/SEP 토끼굴 v7 - 에디션.html`
결과물: `design/v8-정렬.html`

영문 폰트는 지시대로 그대로 둠 — **Old Standard TT** (라틴), Hahmlet (한글), JetBrains Mono (기계 문자열).
색·지면 비유·조판 애니메이션도 v7 그대로. 아래 3가지만 손댔다.

---

## 1. 이유 없이 표기된 정보 삭제

지시 대상이 없거나, 같은 말을 두 번 하거나, 항상 같은 값인 표기를 뺐다.

| 삭제 | 이유 |
|---|---|
| `Late edition` | 이 지면에 이른 판이 없다. 가리키는 대상이 없는 신문 의상 |
| `No. 001` + `Vol. 001` | 서로 다른 두 번호 체계가 둘 다 001에 고정. 하나도 증가하지 않는다 |
| `Page 1 of 1` | 항상 1 of 1 |
| `Edition 001` (하단) | 위 두 개와 같은 말의 세 번째 반복 |
| `· N articles` (하단·상태줄) | 개수는 라우팅의 부수효과. 지면을 보면 이미 보인다 |
| `동료 심사 · 무료 열람` | SEP 홍보 문구. 이 지면이 할 말이 아니다 |
| `Editor's pick` 도장 (-2.4° 회전) | 섹션 제목 `Lead story / 먼저 읽을 것`이 이미 같은 말을 한다. 회전각도 임의값 |
| `.reg` 인쇄 정합 마크 | 이 페이지는 정합을 맞추지 않는다. 순수 장식 |
| 항목마다 붙던 `· plato.stanford.edu` | 상단 출처 줄에서 한 번 말했다. 9번 반복할 이유 없음 |
| 상시 노출 `0 / 60` 카운터 | 45자 넘을 때만 나타나게. 평시엔 알 이유가 없다 |

남긴 것과 그 근거:
- `Edited by Claude Sonnet 4.6` — **누가 조판했는가.** 이 지면의 유일한 발화 주체 표시라 남는다. 적색 밑줄도 이름에만 다시 그었다(전에는 "EDITED BY"까지 덮었다).
- 날짜 — 이 판이 조판된 시점. 실제로 변한다.
- 좌·우 윙 문구 2개 — "내려가는 길", "본문은 이 지면에 인쇄되지 않습니다". 후자는 이 프로젝트의 핵심 전제.
- 하단 손실 문장 — 설계 노트의 원칙("이 페이지가 손실시키는 것을 항상 둔다").
- 섹션의 영문/한글 두 이름 — 한글이 영문의 번역이 아니라 **독자에게 주는 지시**일 때만 유지. 번역이던 `The dispute / 의견이 갈리는 지점`은 `여기서부터 갈라진다`로 고쳐 지시문으로 만들었다.

## 2. 그리드 정렬

v7에는 공유 그리드가 없었다. 밴드마다 제각각이었고 서로 맞을 이유가 없었다:
`1fr auto 1fr`(제호) / `repeat(3,1fr)`(출처줄) / `1fr 172px`(리드) / `1fr 1fr`(2단) / `24px 1fr auto`(목록) / 배경 안내선은 `20%`(=5칸). **172px는 어디에도 대응하지 않는 임의값이었다.**

전부 **12칸 그리드 하나**로 통일:

- `.sheet`가 `repeat(12, 1fr)` + 거터 22px의 원본 그리드.
- 모든 밴드는 `grid-template-columns: subgrid` — 자기 칸을 새로 정의하지 않고 원본 칸선을 그대로 물려받는다. 그래서 어긋날 수가 없다.
- 칸 배정: 제호 3+6+3 · 출처줄 6+6 · 입력 10(2–11) · 부제 6(4–9) · 섹션 헤더 6+6 · 리드 7+5 · 2단 6+6 · 목록 1+7+4 · 하단 8+4.
- 2단 사이 세로 괘선은 거터의 **정중앙**에 놓인다(`padding-left: 거터/2` + `margin-left: -거터/2`).
- 2단 항목은 **행도 subgrid로 공유**한다. v7은 `min-height`로 슬롯을 고정했는데, 그러면 한쪽 제목이 두 줄이 될 때만 맞고 둘 다 한 줄이면 양쪽에 빈 공간이 남았다. 행 subgrid는 한쪽이 늘면 반대쪽 행도 같이 늘어 항상 같은 줄에서 시작한다.
- 조판 전 지면에 **12칸 안내선**이 보인다. `.sheet`와 똑같은 칸 계산식을 쓰므로, 이 선 위에 모든 요소의 끝이 앉는 걸 눈으로 검증할 수 있다.
- 좁은 화면에서는 12칸 → **6칸**. 칸 수만 줄고 정렬 규칙은 같다.
- 제호 3요소에 `grid-row:1`을 명시. 안 하면 칸이 겹칠 때 자동배치가 행을 갈라놔 제호와 윙이 3층으로 흩어진다(v7에서 실제로 그랬다).

## 3. 타이포그래피

**가장 큰 문제: 한글이 라틴 자간을 상속받고 있었다.**
`.la`(letter-spacing .16em, uppercase)와 `.mo` 안에 한글이 들어가 있었다. `.wing em`, `.srcline`의 한글 칸, `.colo`(.2em), `.item .kk`("이해는 없다")가 전부 그랬다. 한글에 0.2em 자간을 주면 글자가 낱개로 흩어진다.
→ `.la` / `.mo` = **라틴 전용**, `.ko` = 한글 전용으로 분리하고 마크업에서 두 문자를 서로 다른 span으로 나눴다.

**`palt` 제거.** v7은 `body` 전체에 `font-feature-settings:"palt" 1`을 걸었다. palt는 일본어 조판용 자간 조정이라 15px 본문 한글에 걸면 자간이 들쭉날쭉해진다. → 큰 글자(헤드라인 입력)에만 남겼다.

**자간을 크기별 4단계로 재설계** (v7은 -.045em / -.035em / -.025em을 크기와 무관하게 섞어 썼다):

| | 값 | 적용 |
|---|---|---|
| `--tr-display` | -.03em | 한글 40px↑ (v7 -.045em → 완화. 한글은 라틴만큼 조이면 받침이 뭉갠다) |
| `--tr-title` | -.02em | 한글 19–32px |
| `--tr-body` | -.01em | 한글 14–18px |
| `--tr-micro` | 0 | 한글 13px↓ (작은 글자를 좁히면 판독이 무너진다) |
| `--tr-la` / `--tr-la-sm` | .14em / .18em | 라틴 대문자. 작을수록 더 벌린다 |
| `--tr-mo` | .06em | 모노 |

v7은 같은 성격의 소문자 라벨에 `.1 / .11 / .16 / .2 / .24 / .26em` 여섯 값을 썼다. 두 값으로 줄였다.

**행간**: 헤드라인 1.1 → **1.16** (한글 받침이 윗줄에 붙던 값). 본문 16px/1.75 = 28px를 세로 기본 단위로 잡고 나머지 여백을 여기 맞췄다. 목록 노트 1.65 → 1.75.

**한글 줄바꿈**: `word-break:keep-all` + `line-break:strict` + `overflow-wrap:break-word`를 `body`에 전역으로 (v7은 일부 요소에만 있어서 `.sechd .ko`, `.colo`, `.foot` 등이 어절 중간에서 끊겼다). 부제는 `text-wrap:pretty` → **`balance`** (2–3줄 짧은 덩어리는 balance가 맞다). 본문 문단은 `pretty` 유지.

**기타**: 숫자에 `tabular-nums`. 커서 색을 적색 → 잉크색으로(커서는 사람의 것이고, 적색은 모델의 손이 닿은 곳에만 쓴다는 규칙).

# v9 — 진단 기반 수정

v8을 두고 "타이포그래피와 그리드가 여전히 어색하다"는 지적을 받고, 추측으로 고치는 대신
전문 자료 서치 + 실측 + `/impeccable`의 두 평가(squint test · mechanical scan)로 원인을 먼저 확정했다.

## 진단 결과

### 확정 버그 — 어절이 쪼개짐

v8은 `word-break:keep-all`과 `overflow-wrap:break-word`를 **같이** 걸었다. 후자가 우선해서
칸이 좁아지면 keep-all을 무시한다. 좁은 상자에서 실측:

| 설정 | 결과 |
|---|---|
| `keep-all` + `break-word` (v8) | 먹었습니**/**다, 만들어졌**/**는지가 ← 쪼개짐 |
| `keep-all` + `normal` (v9) | 먹었습니다 / 만들어졌는지가 ← 유지 |
| `keep-all` + `anywhere` | 쪼개짐 |

→ `normal`로 고치고, 끊을 곳이 없는 URL(`.mo`, `.srcline .r`)에만 `anywhere`를 남겼다.

### Mechanical scan — 스케일이 없었다

| | v8 | v9 |
|---|---|---|
| font-size 리터럴 고유값 | **19개** | **5개** (나머지는 전부 토큰) |
| 간격 고유값 | **23개** | **4개** (나머지는 전부 토큰) |
| 4px 배수 아닌 간격 | **12개** (2·3·5·6·7·9·10·14·18·22·26·34) | 3개 (광학 보정용 2·3·10px) |

v8의 9.5/10/10.5/11.5/12/12.5/13.5 — 4px 폭 안에 7개 값이 몰려 전부 "작은 라벨" 하나를
하고 있었다. 보이지도 않으면서 아무 일도 안 하는 값들이었다.

### Squint test — 위계가 2단으로 무너져 있었다

렌더를 블러 처리해 확인. v8은 거대한 헤드라인 하나만 읽히고 그 아래가 균일한 회색 죽이었다.
네 섹션이 구별되지 않았고, **리드 오른쪽 설명 블록이 리드 제목보다 무거워 보였다**(위계 역전).

## 적용

1. **타입 스케일 7역할** — display / lead 40 / title 26 / sub 20 / body 16 / label 12 / micro 10.
   인접 역할 간 최소 1.25배. 헤드라인 크기도 임의값이 아니라 6단 배열에서 고른다.
2. **간격 4px 스케일** `--s1`~`--s8`, 섹션 리듬은 `--s-sec:56px`(본문 행간 28 × 2).
3. **섹션 3계층** — 리드 3px 괘선 + 20px 섹션명, 본론 1px + 12px, 더읽을거리 hairline + 12px 400.
   블러 상태에서 세 계층이 구분된다.
   리드 제목을 40px/800으로 올려 위계 역전 해소. 스켈레톤용 `min-height`는 `.sec.blank` 안으로
   옮겼다 — v8에서는 조판 후에도 남아 섹션마다 100px 넘는 죽은 공간을 만들었다.
4. **한글 조판**
   - `--prose:"Old Standard TT","Nanum Myeongjo"` — 순서가 중요. 명조를 앞에 두면 라틴까지
     명조가 그려서 지면에 라틴 활자가 두 종류 생긴다(v8의 문제).
   - 혼식 라틴에 `.lat` 클래스로 **105% 광학 보정**. 한글은 전각 상자 중앙에 무게중심이 있고
     라틴은 베이스라인 기준이라, 같은 크기로 두면 라틴이 아래로 내려앉아 보인다.
   - 행간을 CJK 기준으로: 본문 1.75(권장 1.7 내외), 제목 1.35~1.55.
   - 자간 방향을 **반대로** 잡았던 것 수정. 명조는 정사각 모듈 계열이라 음수 자간이 필요하다
     (Hahmlet 같은 최근 폰트와 반대). v8은 Hahmlet에 과한 음수 자간을 주고 있었다.
   - 본문 회색을 `--ink-3`(대비 3.5:1) → `--ink-2`(8.9:1)로. 4.5:1 미달이었다.
5. **서체 교체** — Hahmlet(저대비 슬랩) → **Nanum Myeongjo**(고대비 명조).
   Old Standard TT가 세로 스트레스·고대비 Didone 계열인데 Hahmlet은 정반대여서
   한 지면에서 두 활자가 다른 시대를 말하고 있었다. 영문 폰트는 지시대로 유지.

## 검증

- 500 / 700 / 900 / 1200 / 1400px 전 폭에서 가로 스크롤 0 (`scrollWidth == clientWidth`).
- 조판 전 상태에서 12칸 안내선이 보인다 — 모든 요소의 끝이 그 선 위에 앉는지 눈으로 확인 가능.

# 눈으로 잡은 것 ①  제호 — "가운데가 오목해 보인다"

측정 도구: `design/tools/measure-ink.js` (콘솔에 붙여넣고 `measureMasthead()`)

## 원인 — 두 가지가 겹쳤다

처음엔 세로 정렬 문제로 의심했지만 **측정해보니 편차가 1.4px**뿐이었다. 보일 리 없는 값이다.
진짜 원인은 크기였다.

| | em 대비 잉크 |
|---|---|
| Old Standard TT 대문자 | **0.73em** (캡높이~베이스라인만 채움) |
| Nanum Myeongjo 한글 | **0.945em** (전각 상자를 거의 꽉 채움) |

그래서 **42px로 지정한 제호의 실제 잉크 높이가 30.7px**이었고,
**12px 한글 두 줄 귀(ear) 블록이 30.6px**이었다. 둘이 똑같았다.

신문 제호는 귀를 압도해야 하는데 같은 높이니 가운데가 주저앉아 보인 것이다.
제호가 6칸(480px)에 갇혀 있어 더 키울 수도 없었다.

## 수정

- 제호를 **전폭(`grid-column:1/-1`)**으로 풀고 `clamp(26px,4.6vw,64px)`까지 키움 → 캡높이 47px = 귀 블록의 **1.5배**
- 귀는 양 끝 칸(1–3 / 10–12)에 그대로 두고 **같은 행에 겹쳐** 앉힘 — 신문 제호의 원래 구조
- `align-items:end` → **`center`**, 귀에 `--mh-optical:9px` 광학 보정.
  라틴 대문자는 디센더가 없어 캡 덩어리가 줄상자 위쪽에 앉기 때문. **측정 편차 -0.03px**

정렬 방식을 7가지 재서 고른 결과다:

| 시안 | DELTA |
|---|---|
| 원래(6칸, align:end) | +1.43px |
| 전폭 + align:end | −10.14px |
| 전폭 + last baseline | −8.73px |
| 전폭 + `text-box:cap alphabetic` | −9.41px |
| 전폭 + center, 패딩 0 | −4.53px |
| **전폭 + center + 9px 보정** | **−0.03px** ✓ |

901~1800px 전 폭에서 제호와 귀의 최소 간격 31px 확보 확인(충돌 없음).

**주의:** `--mh-optical:9px`는 간격 스케일이 아니라 측정으로 얻은 광학 보정값이라 4px 배수가 아니다.
제호나 귀의 크기를 바꾸면 `measureMasthead()`로 다시 재야 한다.

# 눈으로 잡은 것 ②  발행표기 — "가운데 정렬이 안 된 것 같다 / 들쭉날쭉하다"

## 원인 — 세 가지

**1. 가운데 정렬은 오차 0.00px였다.** 기하학적으로는 완벽했다.
문제는 줄 안에서 **유일하게 강한 마크인 적색 밑줄이 중심에서 16px 왼쪽**에 있었다는 것.
눈은 가장 강한 마크로 중심을 잡는데, 오른쪽의 회색 날짜는 무게가 없어 받쳐주지 못했다.
→ 기하학적 중심 ≠ 광학적 중심.

**2. 정렬 논리가 두 개 겹쳐 있었다.** 발행표기는 **가운데 정렬**, 바로 아래 출처줄은 **좌우 끝 정렬**.
12칸 그리드를 깔아놓고 이 줄만 그리드 밖에 있었다.

**3. 띠 높이가 달랐다.** 같은 12px 메타 정보 두 줄인데 45.0px vs 36.2px.

## 수정

두 줄 모두 **6칸 + 6칸**으로 통일하고 가운데 정렬을 버렸다. 구분자 `·`도 불필요해져 삭제.

측정 결과 — 왼쪽 글자가 모두 content 왼쪽 끝에, 오른쪽 글자가 모두 오른쪽 끝에 **오차 0.0px**:

| | 왼쪽 글자 | 오른쪽 글자 |
|---|---|---|
| 제호 귀 | 208.0 | 1192.0 |
| 발행표기 | 208.0 | 1192.0 |
| 출처줄 | 208.0 | 1192.0 |
| content 경계 | 208.0 | 1192.0 |

제호 블록 전체가 **두 개의 세로선**에만 매달리게 됐다.

세로 잉크 중심이 줄마다 0.9px씩 다른 건 **고치지 않았다** — 베이스라인은 이미 맞아 있고,
그 차이는 한글이 모노 대문자보다 잉크가 높아서 생기는 정상적인 결과다. 맞추면 오히려 틀어진다.

## 후속 — 두 줄을 한 줄로

양 끝 정렬로 바꾸고 나니 **두 줄 다 가운데가 비어** 지면이 횡해졌다. 정렬이 아니라 분량 문제였다.
다시 「이유 없는 정보 삭제」를 적용하니 두 줄 중 절반이 지워졌다:

| 지운 것 | 이유 |
|---|---|
| `본문을 읽을 곳 — 스탠퍼드 철학 백과사전` | 제호 왼쪽 귀 "스탠퍼드 철학 백과사전으로 내려가는 길"이 **이미 하는 말** |
| `Aug 19, 2026` | 이 지면 어디서도 참조되지 않음. 판(edition) 개념을 이미 뺐으므로 날짜만 남을 이유가 없다 |

남은 둘이 한 줄에 들어간다 — **왼쪽 = 누가 조판했는가 · 오른쪽 = 본문이 어디 있는가.**
빈 가운데를 채우려 하지 않고 줄 수를 줄여 해결했다.

# 눈으로 잡은 것 ③  입력 화면 — 주인공을 사용자의 질문으로

## 문제

가장 큰 자리를 **예시 질문**("인공지능의 마음이란 무엇일까?")이 차지하고 있었다.
사용자의 말이 아니라 우리가 쓴 문장이 지면의 주인공이었다.
그 주위로 `START HERE → 오늘의 헤드라인`, 설명문, `SET THE TYPE`, `조판하기 →`가
각각 떨어져 앉아 입력보다 더 많은 설명을 하고 있었다.

## 수정 — 네 요소짜리 조판 블록

| | 전 | 후 |
|---|---|---|
| eyebrow | `START HERE → 오늘의 헤드라인` (표지 하나가 두 번 말함) | `START HERE` 만 |
| headline | 예시 질문 (실제 사용자 말이 아님) | **입력 안내가 곧 placeholder** — "궁금한 것을 한 줄의 헤드라인으로 써보세요." |
| deck | "질문을 헤드라인처럼 쓰면…" (헤드라인 안내와 정보 중복) | "편집자는 답을 대신 쓰지 않습니다. SEP 원문으로 들어갈 읽기 순서를 골라드립니다." |
| CTA | `SET THE TYPE` + `조판하기 →` 2단, 긴 괘선 사이에 부유 | `조판하기 →` 하나 |

역할 분리: **헤드라인 = 내가 무엇을 하면 되는가 · 덱 = 이 지면이 내 질문으로 무엇을 하는가.**

핵심 인터랙션: 타이핑하는 순간 안내가 사라지고 **사용자의 질문이 같은 자리·같은 크기를 그대로 넘겨받는다.**
별도 검색창으로 이동하지 않는다. 그래서 안내문을 hero copy 가 아니라 `placeholder` 로 넣었다.

## 이 과정에서 잡은 것 두 가지

- **placeholder 대비**: 기존 `rgba(18,22,31,.17)` = **1.42:1**. 예시 질문일 때는 몰라도
  이제 이 화면의 **유일한 안내문**이라 읽혀야 한다. `.50` = **3.32:1** 로 올렸다
  (대형 텍스트 기준 3:1 통과, 잉크색 9:1 보다는 확실히 연함). `--placeholder` 토큰.
- **덱 줄바꿈**: `SEP` 이 1행 끝에 홀로 남고 `원문으로` 가 다음 줄로 떨어졌다.
  `&nbsp;` 로 묶어 지금은 문장 마침표에서 깨끗하게 나뉜다.
  모바일에서는 안내문이 "궁금한 것을 한 줄의 / 헤드라인으로 써보세요." 로 나뉜다.

## 남은 판단 하나

덱 문구의 "골라**드립니다**"는 지면의 나머지 어조(`인쇄되지 않습니다`, `조판합니다`)보다 공손하고,
`design-notes.md` §4 의 "보조자 어휘 금지" 와 미묘하게 충돌한다.
지시하신 문장 그대로 두었으니 바꿀지는 판단해 주시면 된다 (예: `골라 둡니다`).

# 눈으로 잡은 것 ④  결과 영역 — 그리드가 아니라 그리드의 결과

## 문제

네 섹션이 **같은 행 구조를 반복**하고 있었다(6+6, 6+6, 1+7+4). 거기에 12칸 안내선까지
노출돼 있어 newspaper layout 이 아니라 **wireframe / debug grid** 로 읽혔다.

> Do not show the grid. Show the result of the grid.

## 수정 — 섹션마다 다른 조판

칸 안내선(`#board.empty` 의 repeating-gradient)과 `--guide` 토큰을 삭제했다.
네 섹션은 이제 서로 다른 구성을 가진다. **블록의 크기와 위치가 읽는 순서를 말한다.**

| 섹션 | 조판 | 칸 |
|---|---|---|
| **LEAD STORY** | 지면을 지배하는 한 덩어리 + 좁은 측면 노트 단 | 제목 `1–10` (56px) · 노트 `10–13` (12px, 좌측 괘선) |
| **BACKGROUND** | 크기가 다른 두 덩어리. 넓은 쪽 제목이 더 크다 | `1–6` (26px) · `6–13` (40px) |
| **THE DISPUTE** | 마주보는 두 단. **여기만 좌우 대칭** | `1–7` · `7–13`, 가운데 잉크 괘선 |
| **DEEPER DOWN THE HOLE** | 계단처럼 갈라져 내려간다 | 행마다 시작 칸이 하나씩 밀림 `1–10 / 2–11 / 3–12 / 4–13` |

마지막 섹션은 이름이 말하는 형태를 그대로 취한다 — 항목이 하나씩 오른쪽 아래로 내려간다.

## 빈 상태

칸 안내선 대신, **각 블록이 앉을 자리만** 옅은 면(`rgba(18,22,31,.035)`)과
머리카락 테두리로 암시한다. 모서리는 각지게 — 카드가 아니라 아직 인쇄되지 않은 지면의 칸이다.
dummy text rules 는 본문이 앉을 좁은 단에만 넣고 큰 면은 민무늬로 뒀다(참고 이미지의 큰 사각형처럼).

빈 상태에서 잡은 것: `facing` 은 채워졌을 때만 행을 subgrid 로 공유해야 한다.
빈 상태에서 subgrid 를 유지하면 **빈 행이 0 으로 접혀 `min-height` 가 먹지 않는다** —
두 블록이 실처럼 납작해졌다. `.sec.blank` 에서 `grid-row:auto;display:block` 으로 푼다.

좁은 화면에서는 비대칭 조판이 성립하지 않으므로 모든 블록을 한 단으로 쌓고 계단도 편다.
