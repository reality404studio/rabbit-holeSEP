# 검출 실패 기록 — 도구가 틀렸던 열 번

Rabbithol.SEP 리디자인(2026-08) 세션에서 **자동 검사가 틀렸거나, 맞았는데 쓸모없었던** 사례.
`kr-typography.draft.md` 가 "무엇이 옳은가"라면 이 문서는 **"검사를 어디까지 믿을 수 있는가"** 다.

스킬/훅 설계에 쓰라고 따로 뺐다. 결론만 먼저:

> **도구는 "깨끗하다"고 말할 자격이 거의 없다.**
> 미검출·오탐·정확하지만 엉뚱한 답, 세 가지가 전부 나왔고 셋 다 비용이 달랐다.

---

## A. 미검출 — "깨끗하다"고 했는데 아니었던 것

### A-1. 파서가 없으면 검출기가 findings 0 을 뱉는다 ★가장 위험

impeccable `detect.mjs` 를 v9 에 처음 돌린 결과:

```
impeccable detect: DEGRADED - HTML parser modules unavailable
(htmlparser2, css-select, css-tree, domutils).
Falling back to regex matching. Custom properties, selector matching and
computed contrast are NOT evaluated; findings are an undercount,
not a clean bill of health.
[]
```

파서 4개를 설치하고 다시 돌리니 **11건**. 그중에는 `#79808c` 가 **3.49:1** 로
AA 미달인데 **링크에도 쓰이고 있던** 실제 접근성 결함이 있었다.

- **원인**: v9 는 색·크기·간격이 거의 전부 `var()` 토큰이다. 커스텀 프로퍼티를
  해석하지 못하는 검출기에게 이 파일은 **빈 파일과 같다.**
- **도구는 잘못이 없다**: 경고를 명확히 출력했고 "undercount, not a clean bill of health"라고
  못 박기까지 했다.
- **그럼에도 위험한 이유**: `--json` 소비자와 훅은 **stdout 의 `[]` 만 읽는다.**
  경고는 stderr/헤더에 있고, 종료 코드는 0 이다. 자동화에 물리면 그냥 통과한다.

**함의**: degraded 상태는 **종료 코드와 JSON 페이로드 안**에 들어가야 한다.
사람이 읽는 배너로만 알리면 자동화에서 사라진다.

### A-2. 룰 7개 중 4개가 한 번도 발화한 적이 없었다

직접 만든 `kr-typo-detect.mjs` 를 v7/v8/v9 에 돌려 "잘 된다"고 판단할 뻔했다.
실제로는 `kr-word-split`, `kr-stack-order`, `kr-tight-leading`, `kr-missing-keep-all`
**4개가 단 한 번도 실행 경로를 타지 않았다.** 이 프로젝트에 그 결함이 (이미 고쳐서) 없었기 때문.

픽스처 2개를 만들고서야 전부 발화를 확인했다.

**함의**: **발화를 증명하지 못한 룰은 없는 룰이다.** 룰 추가 시 픽스처와 기대값을 강제할 것.
"실제 프로젝트에서 안 걸린다"는 룰이 작동한다는 증거가 아니다.

### A-3. 눈으로만 잡히는 부류가 있다

정적·수치 검사 어느 것도 못 잡고 **사람이 지적한** 것들:

| 지적 | 실제 원인 |
|---|---|
| "제호가 낮아 보인다 / 가운데가 오목" | 캡높이 0.73em 탓에 42px 제호의 잉크가 12px 한글 두 줄과 같은 높이 |
| "EDITED BY 가 가운데 정렬이 안 된 것 같다" | 기하학적으로는 완벽. 강한 마크가 좌측에 쏠림 |
| "이곳 조형이 들쭉날쭉하다" | 가운데 정렬 줄과 좌우 정렬 줄이 인접 |
| "wireframe/debug grid 처럼 보인다" | 12칸 안내선 노출 + 섹션 구조 반복 |

**함의**: 스킬은 "검사를 통과했다"로 끝내면 안 된다. **스크린샷 → 확대 → 블러**를
절차에 포함해야 한다. 자동 검사는 바닥(floor)이지 천장이 아니다.

## B. 오탐 — 도구가 틀린 걸 지적한 것

### B-1. 선택자 매칭이 마지막 클래스만 봐서 생긴 오탐

`kr-latin-tracking-on-hangul` 첫 구현이 v8 에서 2건을 잡았는데 **둘 다 오탐**이었다.

```
.srcline .r { letter-spacing:.06em; text-transform:uppercase }  → "plato.stanford.edu" (라틴)
.foot .r    { letter-spacing:.18em; text-transform:uppercase }  → "Stanford Encyclopedia…" (라틴)
```

- **원인**: 선택자의 **마지막 클래스 하나**(`r`)로 HTML 을 조회했다.
  같은 프로젝트에 `.mh .wing.r`(한글 "인쇄되지 않습니다")가 있어서 뒤섞였다.
  `r`, `l`, `t`, `n` 같은 **짧고 흔한 클래스명**에서 반드시 터진다.
- **수정**: 한글 텍스트 노드마다 **조상 사슬 전체**를 기록하고, 선택자를 우→좌로
  복합 선택자 단위(`.wing.r` 은 두 클래스 모두 요구)로 맞춘다.
  `:not()`·속성 선택자·`+`/`~` 는 **건너뛴다** — 미검출을 택했다.

**함의**: 훅에서 도는 검출기는 **오탐 비용이 미검출 비용보다 훨씬 크다.**
한 번 틀리면 그 다음부터 사람이 전부 무시한다. 애매하면 안 잡는 쪽.

### B-2. font-size 가 아닌 값이 스케일 통계에 섞였다

`kr-scale-noise` 가 v7 의 font-size 고유값을 22개로 보고했는데 목록에 `0.5`, `1` 이 있었다.

```css
#q{ font-size: min(calc(var(--hs,80) * 1px), 10.4vw) }   /* → 1px 로 읽힘 */
#q{ font-size: min(calc(var(--hs,80) * .52px), 12vw) }   /* → 0.5px 로 읽힘 */
```

`calc()` 안의 **승수**를 실제 글자 크기로 읽었다. 개수를 부풀렸고
`0.5/1` 이라는 가짜 "근접 쌍"까지 만들어냈다.

- **수정**: 6px 미만은 버린다. 실제 본문·라벨 크기가 아니다.

**함의**: 단위가 붙어 있다고 그 속성의 값인 게 아니다. `calc`/`clamp`/`min`/`max` 안에서
숫자를 긁어올 때는 **의미 있는 범위로 걸러야** 한다.

## C. 정확한데 엉뚱한 답 — 측정은 맞았고 질문이 틀렸다

### C-1. 제호 — 맞는 값을 재고 틀린 결론을 냈다

"가운데가 오목해 보인다"에 대해 **세로 정렬**을 의심하고 잉크 중심 편차를 쟀다.

```
편차 +1.43px  → "보일 리 없는 값"
```

정렬 시안 3개를 더 재봤지만 최선이 −0.96px. 개선 폭이 의미 없었다.
확대해서 눈으로 본 뒤에야 **다른 양**을 쟀다:

```
제호 잉크 높이 = 30.7px
윙(12px 한글 2줄) 잉크 블록 = 30.6px   ← 똑같다
```

원인은 정렬이 아니라 **크기**였다. Old Standard TT 캡높이가 em 의 0.73 뿐이라
42px 로 지정해도 보이는 글자는 30.7px 이었다.

**함의**: 측정은 정확했다. **무엇을 잴지 고른 게 틀렸다.**
스킬은 단일 측정을 시키면 안 되고 **후보 가설 목록**(정렬 / 크기 / 무게 / 대비 / 간격)을 주고
차례로 재게 해야 한다. 첫 측정이 "이상 없음"이면 가설이 틀린 것이지 문제가 없는 게 아니다.

### C-2. 콜로폰 — 0.00px 인데 사람이 옳았다

```
colo 잉크 중심 = 700.0
지면 중심     = 700.0
차이          = 0.00px
```

기하학적으로 완벽. 그런데 "가운데 정렬이 안 된 것 같다"는 지적이 맞았다.
줄 안에서 **유일하게 강한 마크(적색 밑줄)가 중심에서 약 16px 왼쪽**에 있었고,
오른쪽의 연회색 날짜는 무게로 받쳐주지 못했다.

**함의**: **기하학적 중심 ≠ 광학적 중심.** 중심을 잴 때는 잉크 범위만이 아니라
**무게 분포**(굵기·색 대비·장식 마크 위치)를 같이 봐야 한다. 지표를 하나만 내면 사람을 오도한다.

### C-3. 최신 스펙이 정답일 거라는 가정

혼식 정렬을 `text-box: cap alphabetic` 으로 풀려 했다. 캡높이 기준으로 줄상자를
잘라주는 속성이니 이론상 맞는 도구다. 실측:

| 시안 | 편차 |
|---|---|
| `align-items:center` | −2.53px |
| **`text-box: cap alphabetic`** | **−9.41px** ← 더 나빠짐 |
| `center` + 광학 보정 9px | −0.03px |

지원 여부는 `CSS.supports()` 로 `true` 확인까지 했다. 지원되는데 결과가 나빴다.
(2줄짜리 한글 블록을 함께 트림하면서 기대와 다르게 동작한 것으로 보이나 **원인 규명 안 함.**)

**함의**: "올바른 최신 속성"을 근거로 채택하지 말 것. **재고 이기는 쪽을 쓴다.**

## D. 도구 밖에서 난 사고 (참고)

조판 검출기의 영역은 아니지만 같은 세션에서 조용히 깨진 것들.

### D-1. `:last-of-type` 을 클래스 기준으로 착각

```css
.meta:last-of-type{ border-bottom:1px solid var(--ink) }   /* 의도: 마지막 .meta */
```

`:last-of-type` 은 **엘리먼트 타입** 기준이다. `.colo` 와 `.srcline` 둘 다 `div` 이고
형제 중에 다른 `div` 들이 있어 매칭되지 않았다. 제호 블록을 닫는 잉크 실선이
머리카락 굵기로 빠졌고, **2배 확대 스크린샷을 보고서야** 발견했다.

→ 일반 CSS 린트 영역. 한글 조판 스킬이 잡을 것은 아니지만, **"조용히 시각적으로만
깨지는 CSS 오해"** 부류가 존재한다는 기록.

### D-2. 빈 subgrid 행이 0 으로 접혀 `min-height` 가 죽었다

빈 상태 블록에 `min-height:130px` 을 줬는데 THE DISPUTE 두 블록만 실처럼 납작해졌다.
`.facing > .item` 이 `grid-row:1/5; grid-template-rows:subgrid` 인데
내용이 비면 부모의 auto 행들이 전부 0 이 되어 자식 높이가 그것에 묶였다.

→ `.sec.blank` 에서 `grid-row:auto; display:block` 으로 풀어 해결.
**subgrid 는 채워졌을 때만 쓰는 게 안전하다.**

## 스킬 설계에 주는 함의 (요약)

| 실패 유형 | 설계 요구사항 |
|---|---|
| A-1 degraded → `[]` | 미적용 상태를 **종료 코드와 JSON 안에** 넣는다. 배너로만 알리지 않는다 |
| A-2 미발화 룰 | 룰마다 **픽스처 + 기대값** 강제. 발화 증명 없으면 룰 아님 |
| A-3 눈으로만 보임 | 절차에 **스크린샷 → 확대 → 블러(squint)** 포함. 검사는 바닥이지 천장이 아님 |
| B-1 오탐 | 훅에서는 **오탐 비용 ≫ 미검출 비용**. 애매하면 건너뛴다 |
| B-2 값 오독 | `calc/clamp/min/max` 에서 긁은 숫자는 의미 범위로 거른다 |
| C-1 엉뚱한 측정 | 단일 측정 금지. **후보 가설 목록**을 주고 차례로 재게 한다 |
| C-2 광학 ≠ 기하 | 중심·정렬은 **잉크 + 무게 분포** 두 지표를 함께 낸다 |
| C-3 최신 스펙 | 스펙 적합성이 아니라 **측정 결과**로 채택한다 |

### 아직 못 푼 것

- **광학 보정값(`--mh-optical: 9px`)에 공식이 없다.** 디센더 비율에서 유도해봤으나 안 맞았다.
  현재는 폰트 조합마다 재는 수밖에 없다.
- **`text-box` 가 왜 나빴는지 모른다.** 원인 규명 안 함.
- 측정은 전부 **Chrome 헤드리스 한 곳**에서만. Safari/Firefox 미확인.
